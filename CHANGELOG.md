# История версий

## v1.4.2 — 2026-11-05

Замечание постановщика: в Excel сворачивалась только верхняя группировка (регион), категория — нет.

Причина: уровни структуры выводились из подытогов, а в шаблоне подытоги есть только у региона,
поэтому все детали попадали на один уровень и Excel группировал их по границам строк «Итого».

Исправление: иерархия строится по путям групп, а не по подытогам. Первая строка каждой категории
остаётся видимой опорой (уровень 1), её детали уходят на уровень 2. Результат на `sales-summary`
за 1–10 марта:

| Уровень | Строк | Что это |
|---|---|---|
| 0 | 9 | подытоги регионов и общий итог |
| 1 | 22 | опорные строки категорий (видны при сворачивании деталей) |
| 2 | 2 726 | детальные строки |

Сворачивание: кнопка «2» скрывает детали, оставляя по строке на категорию; «1» скрывает категории,
оставляя подытоги регионов. e2e проверяет наличие обоих уровней.

## v1.4.1 — 2026-11-05

Исправления по замечаниям постановщика к версии 1.4.

### Excel: вернулось сворачивание

- строки получили уровень структуры Excel (`outlineLevel`), включён `outlineProperties.summaryBelow`:
  у детальных строк — уровень группировки, у подытога группы — на уровень выше, итог — вне структуры;
- глубину берём по фактическим подытогам: если подытоги только у верхней группы, детали идут уровнем 1,
  а не «висящим» вторым уровнем без родителя (иначе в Excel нет кнопок «+»);
- работает штатное сворачивание Excel (кнопки 1/2 слева, «−» у группы); свёрнутость экрана не переносится.

### Печать: таблица больше не пропадает

Причина: у контейнера таблицы `contain: strict` — при печати он схлопывался в 0 px, браузер
не пагинировал содержимое, в PDF оставались только canvas-диаграммы. Что изменено:

- в `@media print` добавлено `contain: none` — контейнер получает фактическую высоту таблицы;
- `window.print()` вызывается после фактической отрисовки: `nextTick` + два кадра `requestAnimationFrame`
  + 250 мс на снятие раскладки (иначе в макет попадали диаграммы и пустое место);
- кнопка показывает состояние «Готовим печать…» и защищена от повторного нажатия;
- лимит печати снижен с 20 000 до **5 000** строк: полный DOM на 24 000 строк браузер строит слишком
  долго; сверх лимита — `PRINT_LIMIT` с предложением Excel.

### Замеры (10 дней марта, 2 748 строк)

| Проверка | Значение |
|---|---|
| Excel: строк в файле | 2 757, объединений 28, `outlineLevel`=1 у 2 748 строк |
| Excel: деньги и проценты | `# ##0` и `0.00 %`, ячейки — числа |
| Печать: строк в макете | 2 755 (данные + подытоги + итог) |
| Печать: высота контейнера | 71 684 px (до исправления — 0 px) |
| Печать: время до вызова `print()` | ≈ 1,05 с на 2 748 строках |
| Печать 24 723 строк | отказ `PRINT_LIMIT`, `window.print()` не вызывается |

`REP_E2E=1 ./scripts/check.sh` → `ALL CHECKS PASSED`: e2e 29, включая проверки уровней структуры
в файле и полного макета при `media: print`.

## v1.4.0 — 2026-11-05

Экспорт в Excel и печатный вид (ADR-28, фаза Ф8). Принято постановщиком.
Чек-лист — `docs/dod.md`, раздел «Приёмка версии 1.4»; проект — `docs/export-design.md`.

### Excel

- кнопка «Excel» в шапке отчёта: книга собирается **на клиенте** из модели витрины (ExcelJS 4.4.0, MIT,
  ленивый чанк — бандл отчёта не вырос);
- лист «Отчёт»: объединения многоуровневой шапки, строки, подытоги, общий итог, объединения групп,
  заморозка шапки, автофильтр, ширины колонок из `styles.columns`;
- числа остаются числами: `numFmt` из `format.js` (`# ##0`, `0.00 %`, `dd.mm.yyyy`, валюта), отрицательные
  в скобках; даты пишутся как даты;
- стили зон и совпадения правил: шрифт, начертание, цвета текста и фона, границы;
- лист «Параметры»: имя, подпись (NAME), значение, отчёт, дата выгрузки;
- имя файла `<id>-<ГГГГ-ММ-ДД>.xlsx`; свёрнутые на экране группы выгружаются развёрнутыми;
- диаграммы не переносятся (решение PO); серверный экспорт (`libxlsxwriter`) отложен как запасной путь.

### Печать

- кнопка «Печать / PDF»: `window.print()`, PDF через диалог браузера;
- `@media print`: скрыты панель параметров, тулбар и кнопки, фон белый, таблица без виртуализации;
- шапка повторяется на каждой странице (`table-header-group`), строки и диаграммы не разрываются;
- лимит печати 20 000 строк: сверх — сообщение `PRINT_LIMIT` с предложением выгрузить в Excel.

### Проверки

`REP_E2E=1 ./scripts/check.sh` → `ALL CHECKS PASSED`: ctest 13, vitest 102, golden 15/15,
e2e **29** (включая разбор скачанного файла через ExcelJS и `emulateMedia('print')`).
Замеры: 2 748 строк → файл 2 757 строк (с шапкой и итогом), 28 объединений, подготовка 0,7 с.

### Известные ограничения

- диаграммы в файл не попадают;
- печать больше 20 000 строк не поддерживается (ограничение браузера на построение DOM);
- ExcelJS грузится при первом экспорте (~1 МБ), в офлайне без кеша это заметная пауза;
- условное форматирование переносится как статичные цвета, а не как правила Excel.

## v1.3.0 — 2026-11-05

Принята постановщиком. Администрирование отчётов (ADR-26) и полный перенос SQL в шаблон (ADR-27).
Чек-лист — `docs/dod.md`, раздел «Приёмка версии 1.3».

### Администрирование (ADR-26)

- страница `/admin.html`: список отчётов, создание, правка в редакторе CodeMirror 6 (подсветка JSON,
  номера строк, сворачивание), дублирование, удаление с подтверждением, поиск;
- API записи: `GET /api/admin/reports`, `GET /api/admin/reports/{id}` (полный шаблон с SQL),
  `POST /api/reports`, `PUT /api/reports/{id}`, `DELETE /api/reports/{id}`,
  `POST /api/reports/{id}/validate`, `GET /api/admin/reports/{id}/history`,
  `POST /api/admin/reports/{id}/rollback/{snapshot}`;
- всё это доступно только при `REP_ADMIN=1`, иначе 404 `ADMIN_DISABLED`;
- hot-reload: сохранение применяется **без рестарта** (разбор JSON → атомарная замена под мьютексом);
- история версий в `report_templates_history` (append-only), откат пишется в историю;
- предпросмотр черновика: `?draft=1` + `localStorage`, без записи в БД;
- панель «Параметры и их запросы»: SQL справочников и метка серверной проверки `SELECT ok`;
- серверный guard справочников: только `SELECT`/`WITH`, без `;`, `--`, `/*` и DML/DDL.

### SQL наборов данных в шаблоне (ADR-27)

- `datasets.<key>.sql` вместо `queryId`; `queryId` запрещён на клиенте и на сервере;
- типы колонок определяются по результату запроса (включая даты), проверка `:param::date`/`::int`
  по касту в SQL даёт 422 с именем параметра;
- пустая строка параметра — законное значение («все»), ошибка только при отсутствии ключа;
- `GET /api/reports/{id}` вырезает `datasets.*.sql` и `params[].source.sql`;
- реестр `queries.json` оставлен только со служебным `slow_probe`; 12 шаблонов переведены.

### Проверки

`REP_E2E=1 ./scripts/check.sh` → `ALL CHECKS PASSED`: ctest 13, покрытие `engine/` 97,6 %,
валидация 12 шаблонов, vitest 102, golden 15/15, e2e 27 (включая админку и проверку консоли).
Бандлы: `report-*.js` — 32,8 КБ, `admin-*.js` — 589 КБ (190 КБ gzip); CodeMirror в отчёт не попадает.

### Известные ограничения

- без `REP_ADMIN=1` админки нет (по умолчанию выключена; на демо-стенде включена);
- нет аутентификации — админка только для localhost; read-only роль БД (5.9) обязательна
  перед выносом за пределы доверенного контура;
- серверная валидация шаблона структурная, полная семантика — на клиенте;
- `templates-push.mjs` по-прежнему требует рестарта (пишет в обход процесса).

## v1.2.0 — 2026-11-05

Принята постановщиком. Условное форматирование по правилам в шаблоне (ADR-25).
Чек-лист — `docs/dod.md`, раздел «Приёмка версии 1.2».

### Условное форматирование

- `blocks[].rules[]`: `when` (условие), `apply` (стиль), `scope` (`cell` / `row`), `target`, `zones`, `priority`;
- операторы: `= != > >= < <= between empty notEmpty contains`; условия одиночные либо `all`/`any`
  из 2–5 условий без вложенности;
- сравнение идёт по **сырому** значению строки витрины, поэтому работает и для вычисляемых колонок;
  колонка адресуется полем или заголовком вычисляемой колонки;
- зоны по умолчанию — строки данных и подытоги; итог затрагивается только при явном `zones: ["grandtotal"]`;
- слияние правил по `priority`, при равенстве побеждает объявленное позже;
- семантические цвета: `styles.palette { danger: "#b42318" }` → `"colors": { "text": "danger" }`,
  что позволяет сохранять читаемость в тёмной теме;
- реализация — модуль `report/rules.js` (18 юнит-тестов); правила считаются только для видимого окна,
  в модель строк не попадают.

### Новый шаблон

`sales-rules` — отрицательная прибыль красным, маржа ниже 20 % янтарным фоном, суммы от 50 000
подсветкой строки, итог отдельным правилом. Всего в базе 12 шаблонов.

### Проверки

`REP_E2E=1 ./scripts/check.sh` → `ALL CHECKS PASSED`: ctest 13 кейсов, покрытие `engine/` 97,6 %,
валидация 12 шаблонов, vitest 102, golden 15/15, e2e 26.

Замер: 50 000 строк с четырьмя правилами — 1,47 с (без правил 1,63–1,71 с), 27 строк в DOM.

### Известные ограничения (без изменений)

переменная высота строк; значки ▲/▼ и данные-бары в правилах; условная логика через выражения
(только `all`/`any`); hot-reload шаблонов; read-only роль БД для справочников (задача 5.9) — на финал.

## v1.1.0 — 2026-11-05

Принята постановщиком. Оформление и форматы задаются шаблоном; SQL справочников параметров переехал
в шаблон. Полный чек-лист — `docs/dod.md`, раздел «Приёмка версии 1.1».

### Стили таблиц из шаблона (ADR-23)

- секция `styles` (верхний уровень) + `blocks[].styles` + `columns[].style`; порядок применения:
  умолчания → `preset` → `styles` → `styles.<зона>` → блок → колонка;
- зоны отдельно: `header`, `body`, `subtotal`, `grandtotal` — шрифт, цвета текста и фона, выравнивание,
  вертикальное выравнивание, отступы;
- раскладка: `rowHeight`, `headerHeight`, `subtotalHeight`, `grandtotalHeight`, `cellPadding`,
  `borders` (`none`/`horizontal`/`grid`), `zebra`, `stripeColor`, `tableLayout`;
- колонки: `width` в px или `%`, `minWidth`, `maxWidth`, `align`, `headerAlign`, `format`;
- пресеты: `default` (вид 1.0), `compact`, `print`, `dark`;
- реализация — CSS-переменные на корне таблицы и классы зон, без inline-стилей на ячейках;
  виртуализация переведена на префиксные суммы высот (строки, подытоги и итог могут быть разной высоты).

### Выравнивание и форматы чисел

- `layout.numericAlign` — политика для числовых колонок (`right` по умолчанию, `left`, `center`, `inherit`);
- `headerAlign` у колонки — заголовок можно выровнять иначе, чем данные;
- форматы: `number`, `integer`, `percent`, `currency`, `date` — строкой или объектом
  (`style`, `decimals`, `group`, `decimal`, `prefix`, `suffix`, `negative`: `minus`/`parentheses`);
- резолвер `report/format.js`, 12 юнит-тестов; формат из `styles.columns` сильнее формата колонки.

### Справочники параметров: SQL в шаблоне (ADR-24, заменяет часть ADR-22)

- `params[].source.sql` — обязателен для `kind: "lookup"`; `queryId` удалён и запрещён валидатором;
- API: `GET /api/reports/{reportId}/lookups/{param}?<родитель>=…`, `GET /api/lookups/{id}` удалён;
- `GET /api/reports/{id}` вырезает `sql` из ответа — клиент SQL не видит;
- серверный кэш и `REP_LOOKUP_TTL_SECONDS` удалены, кэш только на клиенте;
- из `queries.json` удалены четыре `lookup_*`; 6 шаблонов переведены на `source.sql`.

### Новые шаблоны

`finance-print` (печатная форма), `ops-dark` (тёмная тема, зебра), `sales-formatted`
(форматы и выравнивание), `sales-typography` (размеры шрифта по зонам, все виды выравнивания).
Всего в базе 11 шаблонов.

### Проверки

`REP_E2E=1 ./scripts/check.sh` → `ALL CHECKS PASSED`: Conan v1, запрет enterprise-компонентов,
лицензии, сборка и `ctest` (13 кейсов), покрытие `engine/` 97,6 % (порог 90 %), сборка фронтенда,
валидация 11 шаблонов, vitest 77, golden 15/15, e2e 25 (включая проверку консоли браузера).

### Известные ограничения

- переменная высота строк и перенос длинного текста не поддерживаются (фиксированные высоты по зонам);
- условного форматирования по значениям нет;
- в диаграммах `yField` — только поле, без выражений;
- hot-reload шаблонов не поддерживается: после `templates-push` нужен рестарт сервиса;
- read-only роль БД для справочников (задача 5.9) отложена на финал — соединение идёт под `postgres`;
- рендер 50 000 категорий — 1,63–1,71 с, принято как норма (бюджет 2 с).

## v1.0.0 — 2026-11-05

Первая версия, принята постановщиком. Состав и известные ограничения — `docs/dod.md`.

### Бэкенд (C++ / Drogon 1.9.8, Conan v1)

- `GET /api/health`, `GET /api/reports`, `GET /api/reports/{id}`, `POST /api/report/data`,
  `GET /api/lookups/{id}`;
- SQL только на сервере: реестр `backend/config/queries.json`, параметры через binding;
- лимит 50 000 строк (`REP_MAX_ROWS`), `statement_timeout` 2 с, коды 404/422/504;
- справочники с кешем в памяти и TTL (`REP_LOOKUP_TTL_SECONDS`);
- шаблоны читаются из PostgreSQL на старте (ADR-21), файлы — источник в репозитории;
- 13 тестов Catch2 (33 assertions) в `ctest`.

### Фронтенд (Vue 3 + Vite + ECharts)

- собственный рендерер `ReportTable.vue` (ADR-20): 50 000 строк — 229 мс, 38 строк в DOM;
- группировка любой глубины, подытоги, общий итог, объединение ячеек, сворачивание групп
  («свернуть/развернуть всё»);
- вычисляемые колонки: `+ - * /`, скобки, `sum/avg/min/max/count/countDistinct`, области
  «строка / группа / итог», статическая проверка выражений в валидаторе и баннер при ошибке;
- диаграммы `line`/`bar`/`pie`, серии по `seriesField`, макет `full`/`half`;
- параметры из БД: `source.kind` = `date`/`datetime`/`static`/`lookup`, мультивыбор в дропдауне
  с чекбоксами, каскад `dependsOn`, в запрос уходит ID, пользователь видит NAME (ADR-22);
- экран списка отчётов с поиском и составом параметров; песочница рендерера `/spike.html`.

### Шаблоны и данные

- 7 шаблонов: `sales-summary`, `sales-by-region`, `sales-matrix`, `sales-detail`,
  `finance-plan-fact`, `ops-sla`, `params-demo`;
- синтетика: `sales` 50 000, `regions` 5, `finance` 576, `ops` 540; `db/init.sh` идемпотентен.

### Проверки
