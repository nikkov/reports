ТЗ: Сервер отчётов (Report Server) — план реализации для Hermes Agent
1. Контекст и цель
Разработать сервер отчётов, позволяющий описывать отчёты декларативно (JSON-шаблон) и отображать их в браузере в виде страниц с текстовыми блоками, таблицами и диаграммами. Ориентир по функциональности таблиц — Microsoft Reporting Services (Tablix), но без визуального конструктора на первом этапе (шаблоны создаются вручную).

Ограничения (жёсткие):

Только компоненты с открытым исходным кодом и свободными лицензиями (MIT / BSD / Apache-2.0).

Диаграммы — только ECharts (Apache-2.0).

Визуальный дизайнер отчётов — вне области работ первого этапа.

2. Архитектура
Слой	Технология	Лицензия	Обязанности
Бэкенд	C++ / Drogon	BSD-3-Clause	Асинхронные запросы к PostgreSQL/MySQL, возврат сырого JSON с данными. Без логики агрегации.
Формат шаблонов	Собственный JSON	—	Описание страниц, блоков, конфигурации таблиц и диаграмм.
Движок отчётов (фронтенд)	Vue 3, самостоятельная разработка	—	Разбор шаблона → запрос данных → вычисление агрегатов и вычисляемых полей → генерация конфигурации vxe-table и опций ECharts.
Таблицы	vxe-table	MIT	Многоуровневые заголовки, объединение ячеек, раскрытие/скрытие строк, рендеринг итоговых строк.
Диаграммы	ECharts	Apache-2.0	Все типы диаграмм.
3. Область работ и этапы
Этап 1. Каркас данных и минимальная сквозная цепочка (2–3 недели)
Цель: отчёт «текстовый блок + плоская таблица + линейная диаграмма» проходит путь от шаблона до рендеринга.

Бэкенд (Drogon):

HTTP-сервис Drogon + подключение к PostgreSQL (асинхронный драйвер).

Эндпоинт GET/POST /api/report/data: принимает reportId и параметры, выполняет предварительно зарегистрированный SQL-запрос, возвращает JSON-массив строк.

Никакой агрегации на бэкенде — все агрегаты считаются на фронтенде.

Фронтенд (Vue 3):

Минимальная схема JSON-шаблона: страница содержит массив blocks; каждый блок имеет type (text | table | chart), dataKey, конфигурацию отображения.

Таблица — только базовые колонки vxe-table (плоские заголовки, без группировки).

Диаграмма — обёртка ECharts с полями xField / yField.

Компонент ReportViewer: циклически рендерит блоки по шаблону.

Критерий приёмки: вручную написанный JSON-шаблон корректно отображается в браузере.

Этап 2. Расширенные возможности таблиц (4–6 недель) — основной объём работ
Цель: покрыть возможности уровня SSRS: многоуровневые заголовки, объединение ячеек, группировка с промежуточными итогами, скрытие строк, общие итоги, вычисляемые столбцы.

Схема шаблона (минимально достаточная):

json
{
  "type": "table",
  "dataKey": "sales",
  "groupBy": ["region", "category"],
  "columns": [
    {"field": "region", "title": "Регион", "group": true},
    {"field": "category", "title": "Категория", "group": true},
    {"field": "product", "title": "Продукт"},
    {"field": "amount", "title": "Сумма", "aggregate": "sum"},
    {"field": "profit", "title": "Прибыль", "aggregate": "sum"},
    {"title": "Рентабельность", "expression": "profit / amount", "format": "percent"}
  ],
  "subtotals": ["region"],
  "grandTotal": true,
  "collapsible": true
}
Работы на фронтенде:

Движок группировок: рекурсивный обход groupBy, построение дерева группировок, вычисление агрегатов по каждой группе (аналог Scope в SSRS).

Генерация конфигурации vxe-table: преобразование дерева группировок в колонки/строки; объединение ячеек группировок через mergeCells; многоуровневые заголовки через children.

Вычисляемые столбцы: вычисление на основе агрегатов области действия (например, sum(profit)/sum(amount)), а не только полей текущей строки.

Строки промежуточных итогов: генерация итоговых строк для каждой группировки и вставка в нужные позиции данных.

Скрытие строк: использование раскрытия/скрытия строк vxe-table, привязка состояния переключения к узлам группировки.

Общие итоги: фиксированная итоговая строка в подвале таблицы; данные подвала должны быть выровнены по листовым колонкам.

Известные риски:

При совместном использовании footer-method и mergeCells в vxe-table возможна рассинхронизация структуры — данные подвала строго выравнивать по листовым колонкам.

После вставки строк промежуточных итогов индексы mergeCells нужно пересчитывать; все правила объединения вычислять после завершения группировки и вставки итоговых строк.

Критерий приёмки: шаблон с трёхуровневой группировкой, промежуточными итогами, вычисляемыми столбцами и раскрытием/скрытием строк корректно отображается; значения агрегатов верны.

Этап 3. Интеграция диаграмм и типизация страниц (2 недели)
Цель: диаграммы используют те же источники данных, что и таблицы; поддерживаются разные типы.

Работы:

Расширить type в шаблоне до chart; указать chartType (line / bar / pie), поля измерений и метрик.

Переиспользовать результаты агрегации движка группировок для передачи в ECharts — диаграмма и таблица используют один и тот же набор агрегированных данных.

Макет страницы: вертикальный поток текстовых блоков, таблиц и диаграмм; поддержка простого соотношения ширины (full / half).

Этап 4. Инструменты и документация (параллельно)
Валидатор шаблонов: проверка структуры JSON в процессе разработки, локализованные сообщения об ошибках.

Набор примеров шаблонов: сводная таблица продаж, финансовый отчёт, операционный дашборд.

Документация: справочник полей шаблона, семантика выражений, инструкция по добавлению нового отчёта.

4. Технические решения и запасные варианты
Вопрос	Решение	Запасной вариант
Источник данных	Бэкенд возвращает сырые строки, фронтенд агрегирует	При больших объёмах — кэш агрегатов на бэкенде (расширение интерфейса)
Вычисляемые поля	Собственный парсер выражений на фронтенде (4 арифметических операции + ссылки на поля)	Библиотека выражений с открытым исходным кодом (например, expr-eval, MIT)
Сложные макеты	На первом этапе только вертикальный поток	В будущем — сеточный макет (поле span в шаблоне)
Производительность vxe-table	Виртуальная прокрутка; вычисление mergeCells вне цикла рендеринга	Ограничение строк на страницу (пагинация на бэкенде)
5. Критерии готовности проекта (Definition of Done)
Все этапы 1–3 приняты по своим критериям.

Не менее трёх примеров шаблонов проходят валидатор и корректно отображаются.

Документация по формату шаблона опубликована.

Все используемые сторонние компоненты имеют лицензии MIT / BSD / Apache-2.0; список лицензий зафиксирован в репозитории.

Отсутствуют зависимости от коммерческих библиотек (в частности, исключены ag-studio-vue3 и подобные).

6. Явно вне области работ (Out of Scope)
Визуальный конструктор отчётов.

Экспорт в Excel/PDF, drill-through, планировщик рассылки (аналог SSRS Subscriptions).

Аутентификация/авторизация на уровне отчётов (при необходимости — отдельная задача).

Поддержка источников данных, отличных от реляционных БД.
