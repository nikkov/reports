# Выражения в отчётах

Вычисляемые колонки задаются строкой `expression` вместо `field`. Выражение считает фронтенд
(`frontend/src/engine/expr.js`), одинаково для трёх областей видимости: строки данных, группы и общего итога.

## Грамматика

```
выражение := терм (('+' | '-') терм)*
терм      := множитель (('*' | '/') множитель)*
множитель := '-' множитель | первичное
первичное := число | поле | функция '(' поле ')' | '(' выражение ')'
функция   := sum | avg | min | max | count
поле      := [A-Za-z_][A-Za-z0-9_]*
число     := [0-9.]+ ([eE] [+-]? [0-9]+)?
```

Что это значит на практике:

- только четыре арифметические операции, унарный минус и скобки — приоритеты обычные;
- **нет** сравнений, условий, строк, `%`, функций кроме пяти агрегатов;
- аргумент агрегата — всегда имя поля, не выражение: `sum(amount)` верно, `sum(amount * 2)` — ошибка;
- имена полей — из набора данных (`columns` запроса), без кавычек.

## Области видимости

| Где считается | `поле` | `sum(field)` и другие агрегаты |
|---|---|---|
| строка данных | значение колонки в строке | значение в этой же строке (агрегат по одной строке) |
| строка подытога | `null` (поля строки не подставляются) | агрегат по всем строкам своей группы |
| строка общего итога | `null` | агрегат по всем строкам набора |

Поэтому обычная формула пишется через агрегаты и работает на всех уровнях:

```json
{ "title": "Рентабельность", "expression": "sum(profit) / sum(amount)", "format": "percent" }
```

## Пустые значения и деление на ноль

- отсутствующее поле и `null` дают `null`;
- любая арифметика с `null` даёт `null` (не ноль);
- деление на ноль даёт `null`, а не `Infinity`;
- `null` печатается как `—` (или `nullText` блока).

Именно поэтому `sum(profit) / sum(amount)` безопасно: при нулевой сумме ячейка будет пустой, а не «∞».

## Примеры

| Выражение | Смысл |
|---|---|
| `sum(amount)` | сумма по группе/итогу, в строке — значение строки |
| `sum(profit) / sum(amount)` | рентабельность, `format: "percent"` |
| `sum(profit) - sum(cost)` | разница агрегатов |
| `(sum(amount) - sum(cost)) / 1000` | выражение в тысячах |
| `avg(amount) * 2` | удвоенное среднее |
| `count(id)` | число строк в группе |
| `-sum(profit)` | унарный минус |

## Числа

- все расчёты идут в `double`; деньги в данных — целые минорные единицы;
- округление — только при выводе (`decimals`, по умолчанию 1 для `percent`; для `number` — как есть);
- формат `percent` умножает значение на 100: `0,205` печатается как `20,5 %`.

## Типичные ошибки

| Сообщение валидатора | Причина |
|---|---|
| `недопустимый символ «%» в выражении` | процент — это формат, а не оператор |
| `аргумент sum() должен быть именем поля` | в агрегат передали выражение |
| `нельзя указывать одновременно field и expression` | в колонке оба поля |
| `поле «x» отсутствует в таблице этого набора данных` | опечатка в имени поля |

## Как узнать об ошибке

- **Валидатор** разбирает выражение тем же парсером: `round(...)`, `sum(a) > 0`, лишний символ —
  ошибка шаблона с путём колонки; опечатка в имени поля — предупреждение `!`.
- **В отчёте** колонка с синтаксической ошибкой помечается баннером «Ошибка в вычисляемых колонках»
  и знаком `⚠` в ячейках, а не тихим `—`.
- Значение `—` в вычисляемой колонке теперь означает именно пустые данные (например, деление на ноль),
  а не сломанную формулу.

Проверить шаблон: `cd frontend && npm run validate -- ../backend/templates/<файл>.json`.
Юнит-тесты движка: `cd frontend && npx vitest run src/engine/expr.test.js`.
