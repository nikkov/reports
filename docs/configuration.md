# Конфигурация сервера отчётов

Все настройки задаются переменными окружения. Значения по умолчанию — те, что в коде
(`backend/src/main.cc`, `backend/src/env.cc`), они же перечислены ниже.

Порядок применения: **переменная окружения процесса → файл `backend/.env` → значение по умолчанию**.
Файл читается на старте (`REP_ENV_FILE`), уже заданные переменные он не перетирает, кавычки вокруг
значения снимаются. Секреты в git не хранятся: `backend/.env` в `.gitignore`.

## Подключение к PostgreSQL

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PGHOST` | `127.0.0.1` | адрес сервера БД |
| `PGPORT` | `5432` | порт |
| `PGUSER` | `postgres` | основная учётная запись: шаблоны, пользователи, сессии, рассылка, аудит |
| `PGPASSWORD` | — | пароль основной учётной записи |
| `PGDATABASE` | `reporting` | база данных |
| `REP_STATEMENT_TIMEOUT_MS` | `30000` | `statement_timeout` соединения в миллисекундах; по его истечении API отвечает 504 `SQL_TIMEOUT` |
| `REP_DB_POOL` | `8` | размер пула основной роли |

Основная роль должна уметь писать: шаблоны, `users`, `sessions`, `report_subscriptions`,
`subscription_runs`, `audit_log`. Если нужна изоляция чтения — см. ниже.

## Роль только-чтения для данных отчётов

Данные отчётов читаются отдельным пулом (ADR-33): запросы из шаблонов не могут писать, даже если
в них ошибка. Пул не создаётся, если не заданы пользователь и пароль, — тогда чтение идёт основной ролью.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_RO_DB_USER` | — | роль только-чтения (например `reporting_ro`); без неё пул не создаётся |
| `REP_RO_DB_PASSWORD` | — | её пароль |
| `REP_RO_DB_HOST` | значение `PGHOST` | адрес для этого пула |
| `REP_RO_DB_PORT` | значение `PGPORT` | порт |
| `REP_RO_DB_NAME` | значение `PGDATABASE` | база |

Права выдаются `db/init.sh` (роль создаётся `scripts/db-ro.sh`). Пул — фиксированные 2 соединения.
`/api/health` показывает `readOnlyRole: true`, если пул создан.

## HTTP-сервер

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_HOST` | `0.0.0.0` | адрес прослушивания; за реверс-прокси достаточно `127.0.0.1` |
| `REP_PORT` | `8080` | порт; при занятом порте сервер пишет «порт … уже занят» и выходит с кодом 1 |
| `REP_THREADS` | `4` | число потоков drogon |
| `REP_MAX_ROWS` | `50000` | предел строк в ответе `/api/report/data`; больше — 422, лечится серверной агрегацией |
| `REP_MAX_TEMPLATE_BYTES` | `262144` | предел размера шаблона (256 КиБ) при сохранении и загрузке |

## Кэш результатов (ADR-32)

Ключ кэша включает версию набора шаблонов, поэтому публикация или удаление отчёта сбрасывают кэш.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_CACHE_TTL_SECONDS` | `60` | время жизни записи; `0` — кэш выключен |
| `REP_CACHE_MAX_ENTRIES` | `200` | сколько результатов держать |
| `REP_CACHE_MAX_BODY_BYTES` | `2097152` | результаты крупнее (2 МиБ) не кэшируются |

Ответы из кэша помечаются `X-Cache: hit` и поддерживают `ETag`/304. Кэш задерживает свежесть
данных — при частом обновлении уменьшите TTL или задайте `0`.

## Шаблоны отчётов

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_TEMPLATES_SOURCE` | `db` | источник шаблонов: `db` (таблица `report_templates`) или `files` (каталог) |
| `REP_TEMPLATES` | `backend/templates` | каталог для `files` и для `scripts/templates-push.mjs` |
| `REP_QUERIES` | `backend/config/queries.json` | реестр SQL; после ADR-27 используется только служебным запросом `slow_probe`, файл обязан быть валидным, иначе сервис не стартует |

В режиме `db` шаблоны читаются в память на старте: после `scripts/templates-push.mjs` нужен
перезапуск сервера (иначе работают прежние версии).

## Админка и аутентификация

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_ADMIN` | `0` | `1` включает маршруты `/api/admin/**` и запись шаблонов; `0` — 404 |
| `REP_AUTH` | `0` | режим входа: `0` — выключен, `1` — сессии в cookie (ADR-34), `proxy` — личность от прокси (ADR-54) |
| `REP_SESSION_TTL_HOURS` | `12` | время жизни сессии, часы (только режим `session`) |
| `REP_AUTH_PROXY_HEADER` | `X-Remote-User` | заголовок с именем пользователя (режим `proxy`) |
| `REP_AUTH_PROXY_TRUSTED` | `127.0.0.1,::1` | адреса, с которых принимается заголовок; остальным — 403 |
| `REP_AUTH_PROXY_AUTOCREATE` | `0` | `1` — заводить неизвестных пользователей прокси |
| `REP_AUTH_PROXY_ROLE` | `viewer` | роль для таких пользователей |
| `REP_AUTH_PROXY_CACHE_SECONDS` | `60` | кэш «логин → роль»; `0` — проверять в базе на каждый запрос |

Матрица ролей: `viewer` — чтение, `author` — создание и черновики, `admin` — публикация, удаление,
история, `/api/admin/**`, рассылка. Неизвестные маршруты требуют `admin` (безопасное умолчание).

## Рассылка отчётов

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_SCHEDULER` | `1` | `0` — не запускать планировщик подписок (например, если рассылкой занимается отдельный экземпляр) |
| `REP_SMTP_HOST` | — | SMTP-сервер; пусто — письма не отправляются, в журнале `subscription.run` будет ошибка |
| `REP_SMTP_PORT` | `25` | порт SMTP |
| `REP_SMTP_USER` | — | логин; пусто — без аутентификации |
| `REP_SMTP_PASSWORD` | — | пароль |
| `REP_SMTP_TLS` | `1` | `1` — STARTTLS |
| `REP_SMTP_FROM` | `reports@localhost` | адрес отправителя |
| `REP_SMTP_RETRY_ATTEMPTS` | `3` | сколько всего попыток отправки делать при сбое (1 — без повторов) |
| `REP_SMTP_RETRY_DELAY_SECONDS` | `60` | пауза перед первым повтором; дальше удваивается: 60, 120, 240… |

Расписание каждой подписки считается в её часовом поясе (`timezone`, IANA-идентификатор:
`Europe/Moscow`, `Asia/Novosibirsk`); пересчёт «местное время ↔ UTC» с переходами на летнее время
делает PostgreSQL, поэтому «0 9 * * 1-5» — это 9:00 по месту подписки.

Планировщик просыпается раз в 30 с и забирает просроченные подписки через
`FOR UPDATE SKIP LOCKED` — два экземпляра не отправят письмо дважды. При сбое SMTP отправка
повторяется: сначала через `REP_SMTP_RETRY_DELAY_SECONDS`, затем пауза удваивается; повторы
не сдвигают плановое время. После `REP_SMTP_RETRY_ATTEMPTS` неудач подписка остаётся без повтора,
а в журнале появляется запись `subscription.given_up`. Письма с вложением
`csv`/`xlsx` собираются тем же кодом, что HTTP-экспорт.

## Журналы и ретеншен

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_LOG_RETENTION_DAYS` | `90` | записи `audit_log` и `subscription_runs` старше N дней удаляются; `0` — не удалять |

Чистка выполняется при старте и далее раз в 6 часов, в отдельном потоке — независимо от
`REP_SCHEDULER` (выключение рассылки не должно отключать чистку журналов). Факт удаления пишется
в сам журнал действием `logs.purge` с числом удалённых записей и глубиной; в `/api/health` глубина
видна как `logRetentionDays`.

## Фронтенд

Приложение конфигурируется **во время выполнения**, пересборка не нужна (ADR-53):

1. адрес API по умолчанию — каталог приложения: `/reports/report.html` → `/reports/api`, корень → `/api`;
2. переопределение — `<meta name="rep-api-base" content="/reports">` в HTML или
   `window.REP_API_BASE = '/reports'` перед скриптами; полная форма `/reports/api` тоже принимается.

Переменные сборки (только если нужен нестандартный результат):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `REP_BASE` | `./` | база сборки Vite; `./` — относительные ссылки, каталог `dist` переносим |
| `VITE_API_BASE` | — | жёстко зашить префикс API в бандл (обычно не нужно) |

## Пример

```bash
export PGHOST=192.168.0.3 PGPORT=32770 PGDATABASE=reporting
export PGUSER=rep_app PGPASSWORD=...            # основная роль: чтение и запись
export REP_RO_DB_USER=reporting_ro REP_RO_DB_PASSWORD=...   # данные — только чтение
export REP_HOST=127.0.0.1 REP_PORT=8080 REP_ADMIN=1
export REP_AUTH=proxy REP_AUTH_PROXY_TRUSTED=127.0.0.1
export REP_CACHE_TTL_SECONDS=30
export REP_SMTP_HOST=smtp.corp.local REP_SMTP_PORT=587 REP_SMTP_TLS=1
./backend/build/rep
```

Проверить, что настройки применились: `curl -s localhost:8080/api/health` — в ответе видны
`db`, `maxRows`, `readOnlyRole`, `authMode`, `schemaVersion` (версия формата шаблона, сейчас 2)
и `version` (версия приложения из файла `VERSION`).
