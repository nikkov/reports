# Замер рендера: 50 000 строк (DoD §5)

Бюджет из DoD: от начала загрузки страницы до интерактивности (первая строка таблицы видна)
**не больше 2 000 мс** на 50 000 строк.

## Как воспроизвести

```bash
./scripts/build.sh                 # фронтенд рядом с бинарником
./demo.sh                          # сервер :8080
cd frontend && npx playwright install chromium   # если ещё нет
npx playwright test e2e/global-setup.js --reporter=line   # или любой e2e: сохраняет .auth/admin.json
npm run bench                      # node scripts/bench-render.mjs
```

Скрипт `frontend/scripts/bench-render.mjs` открывает `report.html?report=bench-50k` под сессией
`.auth/admin.json`, ждёт появления строк, меряет время через `Date.now()` и Resource Timing, затем
прокручивает таблицу в середину. Результат — JSON; код выхода 1, если бюджет нарушен.

Отчёт `bench-50k` (`backend/templates/bench-50k.json`) — вся таблица `reports_examples.sales`
(50 000 строк, 8 колонок) без фильтров и агрегации.

## Результат (локальная машина, 2026-11-12)

| Прогон | До первой строки | Запрос данных | Клиент (передача, разбор, рендер) | Строк в DOM | Прокрутка в середину |
|---|---|---|---|---|---|
| 1 | 2 385 мс | 1 122 мс | 1 263 мс | 28 | 416 мс |
| 2 | 2 248 мс | 1 041 мс | 1 207 мс | 28 | 407 мс |
| 3 | 2 266 мс | 960 мс | 1 306 мс | 28 | 408 мс |

Первый «холодный» прогон после старта сервера — 3 304 мс (запрос 1 478 мс), в таблицу выше не входит.

- ответ данных — 11,9 МБ JSON, с `Content-Encoding: gzip` — 855 КБ (сжатие уже включено);
- в DOM одновременно 28 строк из 50 000 — виртуализация работает, прокрутка перерисовывает окно
  за ~0,4 с;
- результат стабилен: разброс трёх прогонов — 137 мс.

## Вывод

**Бюджет 2 000 мс не выполняется: 2 248–2 385 мс, отклонение 12–19 %.** Разложение показывает, что
время делится примерно пополам: ~1 000 мс — запрос и подготовка на сервере, ~1 200 мс — клиент
(разбор 11,9 МБ JSON, нормализация строк в плоскую модель, префиксные суммы для виртуализации).
Рендер как таковой дешёвый: в DOM 28 строк и перерисовка окна 0,4 с.

Возможные шаги (не сделаны, отдельная задача):
1. компактный формат ответа (массивы значений + отдельный список колонок) — меньше объём и время
   разбора, ожидаемо 300–600 мс на клиенте;
2. профиль нормализации строк и префиксных сумм (Chrome Performance) — искать лишние проходы;
3. серверный `COPY`/бинарный формат вместо JSON-объектов на строку.

Пока бюджет не выполнен, цифру из спайка (`docs/spike-table.md`, 229 мс) нельзя считать приёмочной:
она измеряла рендер модели без сети и без 50 000 строк JSON.
