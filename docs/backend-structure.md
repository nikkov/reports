# Структура бэкенда (ADR-193)

Разделение `main.cc` на функциональные части началось после v2.44.0: файл вырос до 6 637 строк
и держал внутри всё — конфиг, пул, 48 маршрутов, сборку Excel, планировщик рассылки и запуск.

## Раскладка

| Файл | Что внутри |
|---|---|
| `src/main.cc` | точка входа: конфиг из окружения, пул БД, запуск планировщика, регистрация модулей, `run()` |
| `src/app/context.h` | `AppContext` — общее состояние (пул, шаблоны под мьютексом, черновики, кэш REST, лимиты) |
| `src/app/http.*` | ответы JSON, коды ошибок, `TracedMutex` (диагностика дедлока), актор потока |
| `src/app/db.*` | `runQuery` с таймаутом источника, `describeError`, `requestIp` |
| `src/app/audit.*` | журнал действий: `auditEvent`, `actorOf`, `requestActor`, `purgeOldLogs` |
| `src/app/sse.*` | потоки обновления по событию: регистрация клиента, `notifyChange`, пульс |
| `src/app/template_types.h` | `DatasetInfo`, `TemplateInfo`, `ResolvedDataset` — контракт шаблона |
| `src/app/template_parse.*` | разбор JSON шаблона, миграция версии, схема (`prepareTemplate`) |
| `src/app/template_store.*` | память шаблонов: `applyTemplate`, `dropTemplate`, версия и сброс кэша |
| `src/app/auth_routes.*` | `/api/auth/login`, `/logout`, `/me` |
| `src/app/system_routes.*` | `/api/health` |
| `src/app/admin_reports.*` | все админские маршруты шаблонов (чтение, сохранение, история, откат, черновики, публикация) |

Модуль маршрутов — функция `registerXxxRoutes(AppContext &ctx, ...)`, которую вызывает `main()`.
Маршрут не знает, откуда взялись данные: всё приходит из контекста или параметрами.

## Правила, добытые при переносе

1. **`drogon::app()` пишется с квалификатором.** Внутри `namespace rep::routes` имя `app` перекрывается
   `namespace rep::app`, и `app()` перестаёт компилироваться.
2. **Всё, что стало параметром модуля, захватывается по значению.** В `main()` лямбда жила столько же,
   сколько процесс, и `&applyTemplateInMemory` работал. В модуле это параметр функции: ссылка умирает
   при возврате из `register...`, и обработчик падает на `bad_function_call`.
3. **Тела обработчиков переносятся без правок**, локальные копии объявляются сверху:
   `const auto db = ctx.db;` — так диффы остаются проверяемыми, а поведение — прежним.
4. **Баланс скобок проверяется до сборки.** При вырезании блока легко потерять закрытие функции;
   `awk`-счётчик `{`/`}` ловит это дешевле, чем компилятор.
5. **`AppContext` не владеет объектами** — это указатели на то, чем владеет `main()`. Снимок шаблона
   берётся через `ctx.templateSnapshot(id)` под мьютексом, а не удержанием замка на всю обработку.

## Что проверять после каждого шага

```bash
cd backend && cmake --build build -j$(nproc)
cd .. && REP_E2E=1 ./scripts/check.sh      # полный прогон, а не только сборка
```

После переноса маршрутов — smoke на вынесенный домен: `curl` на сам маршрут с сессией админа,
а не только «сервер поднялся».
