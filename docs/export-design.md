# Экспорт в Excel и печатный вид — проектный план

Цель: отчёт можно отдать наружу — файл `.xlsx` с шапкой, группировкой, подытогами, объединениями
и числами в формате шаблона, и печатная версия страницы для PDF через диалог браузера.

Основание: требование PO 2026-11-05 (доступ отложен, следующий шаг — экспорт и печать).

## 1. Что есть и в чём ограничение

| Механизм | Состояние | Следствие для экспорта |
|---|---|---|
| Модель таблицы | `TableView` строит `view.rows` (`detail`/`subtotal`/`grandtotal`), `merges`, `columns` | это **источник** для экспорта: в DOM только окно виртуализации (~40 строк) |
| Виртуализация | 50 000 строк — 27 строк в DOM | экспорт из DOM невозможен: берём модель целиком |
| Форматы | `report/format.js`: `number`, `integer`, `percent`, `currency`, `date`, `decimals`, разделители, `negative` | переносятся в Excel как числовой формат ячейки |
| Стили | `styles` зон, колонок, пресеты (CSS-переменные) | в Excel — шрифт/цвета/выравнивание на уровне ячейки |
| Правила | `rules` (условное форматирование, inline-стили) | в Excel — цвет/начертание по факту совпадения |
| Печать | `@media print` нет; шапка sticky, тулбар и параметры видны | нужен отдельный печатный режим |

## 2. Excel: где генерировать

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Клиент (ExcelJS, MIT)** — по модели, как на экране | ровно то, что видит пользователь: свёрнутые группы, подытоги, объединения, цвета правил; нет запроса к БД | зависимость ~1 МБ (ленивый чанк); 50 000 строк в памяти браузера (~150–250 МБ) |
| B. Сервер (`libxlsxwriter`, BSD-2) | память сервера, большие объёмы, единый формат для рассылки | дублирование логики группировки/подытогов/правил на C++, риск расхождения с экраном |
| C. Клиент «сырые строки» (SheetJS) без стилей | дёшево | теряются подытоги, объединения, форматы — это не «отчёт» |

**Рекомендация: A** для версии 1.4 (WYSIWYG-экспорт текущего вида) и B — отдельной задачей,
когда появятся объёмы больше 50 000 строк или рассылка по расписанию. Причина: логика группировки,
форматов и правил уже живёт на клиенте; второй её экземпляр на C++ разойдётся с экраном.

Что попадает в файл:

- лист «Отчёт»: шапка (объединения многоуровневого заголовка), строки данных, подытоги, общий итог;
- стили: шрифт/размер/насыщенность, цвета текста и фона, выравнивание, границы по `layout.borders`;
- числа: числовой формат из `format.js` (`# ##0`, `0,00 %`, дата `ДД.ММ.ГГГГ`), чтобы Excel считал,
  а не показывал текст;
- объединения: те же, что на экране (включая группы), но не через границу «свёрнуто/развёрнуто»;
- правила: цвета/начертание по совпадению (без формул условного форматирования Excel — проще и предсказуемее);
- лист «Параметры»: значения параметров и подписи (NAME), дата выгрузки — чтобы файл был самодостаточным;
- заморозка шапки, автофильтр по последней строке шапки, ширины колонок из стилей.

Ограничения: диаграммы в Excel **не переносим** (это отдельный формат, картинка теряет данные);
максимум строк на экспорт — 100 000 (`REP_EXPORT_MAX_ROWS`), при превышении — отказ с сообщением.

## 3. Печать

Печатный вид — тот же отчёт без интерфейса:

- `@media print`: скрыть тулбар, параметры, кнопки; белый фон; чёрный текст; границы `grid`;
- шапка таблицы повторяется на каждой странице (`thead` + `display: table-header-group`);
- запрет разрыва строки внутри группы (`tr { break-inside: avoid }`), перенос по группам;
- колонка группировки не «уезжает»: при печати группы раскрываются полностью;
- страница A4 landscape для широких отчётов, поля 10 мм, масштаб «по ширине» через CSS `@page`;
- вызов — кнопка «Печать / PDF» → `window.print()`, дальше пользователь выбирает PDF в диалоге.

Ключевая развилка: печатать **весь отчёт** (все строки, развёрнутые группы) — честно, но при 50 000
строках браузер построит 50 000 строк DOM; либо **как на экране** (свёрнутые группы и только они) —
легко, но это не отчёт. **Рекомендация:** печать всегда «весь отчёт» с лимитом 20 000 строк
и предупреждением при превышении; для больших объёмов — экспорт в Excel, а не печать.

## 4. Точки интеграции

| Файл | Изменение |
|---|---|
| `frontend/src/report/export/xlsx.js` | новый модуль: `buildWorkbook({template, block, rows, columns, merges, formats, styles, params})` → Blob |
| `frontend/src/report/export/formats.js` | перевод `format.js`-спеки в числовой формат Excel (`numFmt`) |
| `frontend/src/report/TableView.vue` | доступ к модели (`view.rows`) и к «полному» варианту (развёрнутому) для экспорта |
| `frontend/src/components/ReportTable.vue` | печатные классы: `print-header`, `avoid-break`; режим `printMode` без виртуализации |
| `frontend/src/report/ReportViewer.vue` | кнопки «Excel» и «Печать / PDF», передача параметров и шаблона |
| `frontend/src/report/print.css` или scoped `@media print` | печатный макет |
| `frontend/package.json` | `exceljs` (MIT) |

ExcelJS грузится лениво (`await import('exceljs')`) — в бандл отчёта не попадает, только в момент экспорта.

| | **Итого** | | **9,5** |

Критерии приёмки:

1. `.xlsx` открывается в Excel и LibreOffice; числа — числа, даты — даты, проценты — проценты;
2. объединения и подытоги совпадают с экраном (свёрнутые группы экспортируются развёрнутыми);
3. цвета и шрифты зон перенесены, совпадения правил подсвечены;
4. лист «Параметры» содержит подписи выбранных значений;
5. печать: шапка повторяется, группы не разрываются, интерфейс скрыт;
6. лимиты соблюдаются, при превышении — понятное сообщение, а не зависание;
7. бандл отчёта не вырос: ExcelJS в ленивом чанке (проверка размера `report-*.js`).

| ID | Риск | Реакция |
|---|---|---|
| R1 | 50 000 строк в ExcelJS съедят память вкладки | лимит 100 000 + предупреждение; при объёмах — серверный экспорт (вариант B) |

## 7. Решения PO (2026-11-05, приняты)

1. Экспортируется **весь отчёт**: свёрнутые группы выгружаются развёрнутыми.
2. Печать — весь отчёт, лимит 20 000 строк; больше — Excel.
3. Диаграммы в Excel **не переносятся**.
4. Серверный экспорт (`libxlsxwriter`) отложен до объёмов > 50 000 строк или рассылки.
5. Два листа: «Отчёт» и «Параметры».

Уточнения после приёмки (1.4.1): в Excel выставляются уровни структуры (`outlineLevel`,
`summaryBelow`) — сворачивание работает штатными кнопками Excel; при печати контейнер таблицы
теряет `contain: strict`, иначе он схлопывается в 0 px и таблица не попадает в PDF; `window.print()`
вызывается после двух кадров отрисовки; лимит печати — 5 000 строк.

Версия 1.4 реализована: `frontend/src/report/export/xlsx.js`, кнопки в шапке отчёта,
печатные правила в `ReportTable.vue` и `ReportViewer.vue`; e2e 29.

## 7a. Исходные вопросы (история)

1. **Что экспортировать по умолчанию**: «как на экране» (свёрнутые группы) или «весь отчёт»
   с развёрнутыми группами и подытогами? Рекомендация: весь отчёт, а состояние экрана — опцией.
2. **Печать**: весь отчёт (лимит 20 000) или как на экране? Рекомендация: весь отчёт, большие объёмы — Excel.
3. **Диаграммы в Excel**: не переносить (рекомендация) или вставлять картинкой PNG на отдельный лист?
4. **Серверный экспорт** (libxlsxwriter, BSD-2) — планировать в 1.4 как второй путь или отложить
   до появления объёмов/рассылки? Рекомендация: отложить, зафиксировать в ADR как запасной вариант.
5. **Один лист или несколько** (данные, параметры, сводка)? Рекомендация: два листа — «Отчёт» и «Параметры».
