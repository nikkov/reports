# Стили таблиц в шаблоне — проектный план

Цель: внешний вид отчёта задаётся шаблоном, а не кодом рендерера — ширина колонок, высота строк,
шрифты, цвета текста и фона, выравнивание, границы. Отдельно для заголовков, обычных строк,
подытогов и общего итога. Правка стиля не требует пересборки фронтенда: только шаблон в БД.

Основание: требование PO от 2026-11-05 к версии 1.1. Версия 1.0 (`v1.0.0`) стилей не поддерживает:
цвета и шрифты зашиты в `ReportTable.vue`, ширина колонки — единственный настраиваемый параметр
(`columns[].width`, px), высота строки — константа `rowHeight = 26`.

## 1. Что есть сейчас (факты из кода)

| Механизм | Текущее состояние | Следствие для плана |
|---|---|---|
| Ширина колонки | `columns[].width` → `<col style="width: {n}px">` | поддержать px и %, добавить min/max |
| Высота строки | `ReportTable.rowHeight = 26` — одна на все строки | нужны высоты по зонам, иначе шапка и итоги не отличаются |
| Шапка | sticky, высота измеряется в `headerHeight` | высота шапки станет параметром шаблона |
| Виртуализация | `topPad = start × rowHeight`, `bottomPad = (n − end) × rowHeight` | арифметика ломается при разных высотах → префиксные суммы |
| Зоны в CSS | `th`, `td`, `tr.subtotal td`, `tr.grandtotal td`, `td.inherit` | зоны уже разделены, стили навешиваются классами |
| Цвета/шрифты | зашиты в `<style scoped>` | вынести в CSS-переменные на корне таблицы |
| Производительность | 50 000 строк — 229 мс, 38 строк в DOM | бюджет: не хуже +15 % (≤ 265 мс) |

## 2. Модель стилей в шаблоне

Необязательная секция верхнего уровня `styles` + переопределения на уровне блока и колонки.
Совместимость сохраняется: шаблоны без `styles` рендерятся как в 1.0, `version` остаётся `1`.

```json
"styles": {
  "preset": "compact",
  "font": { "family": "system-ui", "size": 13, "weight": 400, "style": "normal", "lineHeight": 1.4 },
  "colors": { "text": "#1c1f23", "background": "#ffffff", "border": "#dfe3e8" },
  "layout": {
    "rowHeight": 24,
    "headerHeight": 32,
    "subtotalHeight": 26,
    "grandtotalHeight": 28,
    "cellPadding": "4px 8px",
    "borders": "horizontal",
    "zebra": true,
    "stripeColor": "#f7f9fc",
    "tableLayout": "fixed"
  },
  "header":     { "font": { "weight": 600 }, "colors": { "text": "#10233d", "background": "#eef3fb" }, "align": "left" },
  "body":       {},
  "subtotal":   { "font": { "weight": 600 }, "colors": { "background": "#f7f9fc" } },
  "grandtotal": { "font": { "weight": 700 }, "colors": { "background": "#eef1f5" } },
  "columns": {
    "amount": { "width": 140, "align": "right", "colors": { "text": "#0b3d2e" } }
  }
}
```

Стиль-объект (одинаковый во всех зонах и у колонки):

| Ключ | Значения | Ограничения |
|---|---|---|
| `font.family` | строка из безопасного списка шрифтов | без `url()`, кавычек-инъекций |
| `font.size` | 8…32 | px |
| `font.weight` | 300…800 | шаг 100 |
| `font.style` | `normal`, `italic` | |
| `font.lineHeight` | 1.0…2.0 | |
| `colors.text`, `colors.background`, `colors.border` | `#rgb`, `#rrggbb`, `transparent` | |
| `align` | `left`, `right`, `center` | у колонки перекрывает зону |
| `verticalAlign` | `top`, `middle`, `bottom` | |
| `padding` | `"4px 8px"` | 0…24 px по сторонам |
| `layout.*Height` | 16…120 | высоты зон |
| `layout.borders` | `none`, `horizontal`, `grid` | |
| `layout.zebra`, `layout.stripeColor` | bool, цвет | |
| `layout.tableLayout` | `auto`, `fixed` | `fixed` при заданных ширинах |
| `columns[].width` | `120` (px) или `"20%"` | 40…2000 px / 1…100 % |
| `columns[].minWidth`, `maxWidth` | px | ≤ `maxWidth` ≥ `minWidth` |

Пресеты (`preset`) — встроенные наборы поверх умолчаний: `default` (как в 1.0), `compact`
(меньше высота и отступы), `print` (крупнее шрифт, чёрные границы, без зебры), `dark`.
Пресет применяется первым, затем `styles`, затем `blocks[].styles`, затем `columns[].style`.

### Порядок применения (от слабого к сильному)

1. встроенные умолчания рендерера (= вид 1.0);
2. `styles.preset`;
3. `styles` (включая `styles.header` / `body` / `subtotal` / `grandtotal` / `columns`);
4. `blocks[].styles` — только для таблиц этого блока;
5. `columns[].style` — перекрывает зону для конкретной колонки.

Ключи сливаются поштучно (deep merge), массивы не сливаются. Итог считается **один раз** на блок:
`resolveStyles(template, block)` → плоский объект `{ table, header, body, subtotal, grandtotal, columns }`.

## 3. Как это попадает в DOM

Важно для производительности: никаких inline-стилей на 50 000 ячеек.

1. `resolveStyles()` → CSS-переменные на корне таблицы: `--rt-font-size`, `--rt-header-bg`,
   `--rt-subtotal-weight`, `--rt-row-height`, `--rt-border-color`, …
2. Зоны уже разделены классами: `thead th` → `header`, `tr.detail td` → `body`,
   `tr.subtotal td` → `subtotal`, `tr.grandtotal td` → `grandtotal`.
3. Ширины — через `<colgroup>` (уже есть) + `min-width`/`max-width` на `col`; `align` колонки —
   класс `num`/`txt`/`ctr` (уже есть `num`).
4. Границы (`horizontal`/`grid`/`none`) — через CSS-переменную и пару правил, не через inline.
5. Зебра — `tr.detail:nth-child(odd)`; при виртуализации индекс берётся из модели строки
   (`row.number`), а не из DOM-позиции, иначе полосы «прыгают» при прокрутке.

## 4. Виртуализация при разных высотах зон

Сейчас `topPad`, `bottomPad` и `start` считаются умножением на одну `rowHeight`. С высотами по зонам:

- модель строк уже содержит `kind` (`detail` / `subtotal` / `grandtotal`) — высота берётся по `kind`;
- один раз на изменение данных/стилей строится массив префиксных сумм `offsets[i]` (Float64Array,
  50 001 элемент ≈ 400 КБ, построение ≈ 1 мс на 50 000 строк);
- `start` — бинарный поиск по `offsets` от `scrollTop` (log₂ 50 000 ≈ 16 шагов);
- `topPad = offsets[start]`, `bottomPad = offsets[n] − offsets[end]`;
- скрытые строки под sticky-шапкой (`hiddenRows`) остаются как есть, но высота шапки — из стилей.

Ограничение версии 1.1: **фиксированные высоты по зонам**, без переноса текста и переменной высоты
отдельной строки. Причины: переменная высота требует измерения строк в DOM и инвалидирует
префиксные суммы при каждом изменении окна — это отдельный проект (см. §8, риск R2).

## 5. Валидатор и схема

Схема (`schema.js`, генерируемая `docs/template.schema.json`):

- `styles` и `blocks[].styles` — объекты с `additionalProperties: false`
  (опечатка `backgroundColor` вместо `colors.background` — ошибка, а не молчаливое игнорирование);
- цвета — шаблон `^#[0-9a-fA-F]{3}$|^#[0-9a-fA-F]{6}$|^transparent$`;
- `font.family` — из allowlist: `system-ui`, `Inter`, `Roboto`, `Arial`, `Georgia`, `Times New Roman`,
  `Courier New`, `monospace` (защита от инъекции CSS и от шрифтов, которых нет на машине);
- числа — в диапазонах из таблицы §2.

Семантический валидатор (`validate.js`) дополнительно:

- предупреждение, если `colors.text` совпадает с `colors.background` (нечитаемо);
- предупреждение, если `font.size < 10` и `layout.rowHeight < font.size × 1.2` (текст не помещается);
- ошибка, если `columns.<field>` ссылается на поле, которого нет в колонках таблицы;
- ошибка, если `minWidth > maxWidth`.

Критерии приёмки:

1. шаблон без `styles` выглядит идентично 1.0 (скриншот `sales-summary` не меняется);
2. стили шапки, строк, подытогов и итога задаются независимо и проверяются в e2e;
3. ширина колонки — px, %, min/max; высоты — по зонам;
4. 50 000 строк — не медленнее 2 с (см. решение ниже), в DOM по-прежнему ≈ 40 строк;
5. ошибка в имени ключа стиля — сообщение валидатора с путём, а не молчаливый дефолт;
6. все 7 существующих шаблонов проходят валидатор и e2e без правок.

## 7.1 Производительность: принятое решение (PO, 2026-11-05)

Замеры на 50 000 строк (два уровня группировки, две диаграммы):

| Что | Значение |
|---|---|
| рендер окна (модель + раскладка + отрисовка) | 1,63 с плоская таблица, 1,71 с с группировкой |
| запрос к API | 2,0–2,6 с (сортировка 50 000 строк в PostgreSQL) |
| строк в DOM | 27 |

Первоначальный ориентир 265 мс (база 229 мс + 15 %) относился к рендереру без диаграмм и оказался
недостижим: основное время уходит на агрегацию 50 000 категорий для ECharts, а не на слой стилей
(табличные отчёты на 540–576 строк рендерятся за 25–58 мс).

**Решение постановщика 2026-11-05: 1,7 с на 50 000 категорий принято как приемлемое.** Критерий
приведён к бюджету DoD («рендер 50 000 строк ≤ 2 с»), задача 5.8 (оптимизация диаграмм) снята.
Если появится требование к интерактивности на таких объёмах — возвращаемся к вариантам серверной
агрегации или `maxCategories` в шаблоне.

## 8. Риски

| ID | Риск | Реакция |
|---|---|---|
| R1 | Разные высоты ломают виртуализацию (смещения, «прыжки» при прокрутке) | префиксные суммы + бинарный поиск; e2e на прокрутку до последней строки |
| R2 | Захочется перенос текста и переменную высоту строки | вне 1.1: требует измерения DOM и инвалидации смещений; отдельная задача с замером |
| R3 | Инъекция CSS через `font.family` / цвета | allowlist шрифтов, строгий regexp цветов, никаких `url()` и `var()` в значениях |
| R4 | Скриншот-эталоны нестабильны (разные шрифты на машинах) | только allowlist-шрифты, `animations: 'disabled'`, `maxDiffPixelRatio: 0.01` |
| R5 | Шаблон становится нечитаемым (стили на каждую колонку) | пресеты + стиль на зону; предупреждение валидатора при > 15 переопределений колонок |
| R6 | Тёмная тема конфликтует с цветами диаграмм | `chart` получает `colors.text` для осей и легенды |

## 9. Решения по открытым вопросам (PO, 2026-11-05)

1. **Переменная высота строк** — отдельной задачей. В 1.1 только фиксированные высоты по зонам:
   перенос текста требует измерения DOM и инвалидации смещений виртуализации.
2. **Условное форматирование** — после базовых стилей, отдельным слоем `rules[]` с выражениями.
   В 1.1 не входит.
3. **Область применения** — таблицы полностью + цвет текста и шрифт осей и легенды диаграмм;
   оформление страницы (заголовок, панель параметров) — позже.
4. **Пресеты** — четыре: `default`, `compact`, `print`, `dark`. Свой брендбук — отдельным пресетом позже.
5. **Хранение** — в шаблоне: `styles` на верхнем уровне, `blocks[].styles` для блока,
   `columns[].style` для колонки, `preset` как общий слой.
